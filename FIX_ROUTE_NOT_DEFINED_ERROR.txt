================================================================================
ROOT CAUSE ANALYSIS
================================================================================

ERROR MESSAGE:
Route [mentor.tasks.show] not defined.

PENYEBAB:
1. Route /{id} untuk show() berada SETELAH route API /{taskId}/submissions
2. Laravel routing mencoba match route dari atas ke bawah
3. Ketika mengakses /mentor/tasks/140, Laravel match ke /{taskId}/submissions
   karena "140" dianggap sebagai {taskId}
4. Route show() tidak pernah tercapai karena sudah di-match oleh route sebelumnya

ADDITIONALLY:
5. Beberapa route penting tidak terdaftar:
   - /tugas-siswa/{siswaId} → untuk halaman daftar tugas per siswa
   - /daftar-tugas → untuk halaman daftar semua tugas
   - /download-submission/{id} → untuk download file submission
   - /api/get-task/{taskId} → untuk fetch data task (used in edit modal)

================================================================================
SOLUSI
================================================================================

STRATEGY:
Reorganize route order - specific routes BEFORE generic routes

PRINCIPLE:
Route dengan pattern lebih spesifik harus dideklarasikan SEBELUM route generic.
Contoh urutan yang benar:
1. /tasks/create              (spesifik)
2. /tasks/api/...             (spesifik dengan prefix)
3. /tasks/tugas-siswa/{id}    (spesifik)
4. /tasks/{id}                (generic - catch all)

IMPLEMENTATION:
Reorder routes di web.php:

BEFORE (SALAH):
```php
Route::get('/{id}', ...)->name('show');              // Line 1
Route::get('/{taskId}/submissions', ...);            // Line 2
```
Problem: /{id} akan match semua pattern, termasuk /api/...

AFTER (BENAR):
```php
Route::get('/daftar-tugas', ...);                    // Spesifik
Route::get('/tugas-siswa/{siswaId}', ...);          // Spesifik
Route::get('/api/...', ...);                         // Spesifik dengan prefix
Route::get('/{id}', ...)->name('show');             // Generic (last)
```

WHY THIS ORDER MATTERS
================================================================================

LARAVEL ROUTING MECHANISM:
Laravel matches routes in the order they are defined. Once a match is found,
it stops and executes that route's handler.

EXAMPLE PROBLEMATIC SCENARIO (BEFORE FIX):
User accesses: /mentor/tasks/api/bidang/TIK/students

Route order:
1. Route::get('/{id}', ...) → MATCHES! (api = {id})
2. Route::get('/api/bidang/{bidang}/students', ...) → NEVER REACHED

Result: 404 or wrong handler executed

EXAMPLE CORRECT SCENARIO (AFTER FIX):
User accesses: /mentor/tasks/api/bidang/TIK/students

Route order:
1. Route::get('/api/bidang/{bidang}/students', ...) → MATCHES! ✅
2. Route::get('/{id}', ...) → NOT CHECKED (already matched)

Result: Correct handler executed
